    2. Einrichtung einer Entwicklungsumgebung

    Hinweis: In den folgenden Schritten verwenden wir das Werkzeug VSCode, um die Dart-Skripte zu testen. Öffnen Sie zwei VSCode-Fenster und öffnen Sie mit [File / Open Folder] die Ordner der beiden Projekte.

    Der TypeScript-Kurs installiert Node.js, ein npm-Projekt ([package.json]), TypeScript selbst samt Typprüfer ([tsc]), einen Skript-Runner, der keine vorherige Kompilierung benötigt ([tsx]), und schließlich ESLint. Das Dart-Pendant zu dieser gesamten Werkzeugkette besteht aus einer einzigen zu installierenden Komponente: dem [Dart SDK] – es kann von [dart.dev] heruntergeladen oder einfacher über einen Paketmanager des Systems installiert werden ([choco install dart-sdk] unter Windows, [brew install dart] unter macOS oder das offizielle APT-Repository unter Linux/Debian/Ubuntu).

    Während TypeScript drei getrennte Werkzeuge erfordert (den Compiler [tsc] zur Typprüfung, [tsx] zum Ausführen eines Skripts ohne vorherige Kompilierung und ESLint für die Stilanalyse), bietet das Dart SDK all dies in einem einzigen Befehl, [dart], der die folgenden Unterbefehle enthält: [dart run] (führt ein Skript aus), [dart analyze] (prüft den Stil – das kombinierte Pendant zu [tsc] und ESLint), [dart pub] (verwaltet Abhängigkeiten, Pendant zu [npm]), [dart format] (formatiert den Code neu, Pendant zu Prettier) und [dart test] (führt die Tests aus).

    2.1. Installierte Werkzeuge überprüfen

    Sobald das SDK installiert ist, überprüfen Sie die Installation in einem Terminal in VSCode:

    PS C:\Data\st-2026\dev\dart\dart-sept-2026-scripts\dart-fundamentals> dart --version
Dart SDK version: 3.12.2 (stable) (Tue Jun 9 01:11:39 2026 -0700) on "windows_x64"

    Der Befehl zeigt die Version des SDK an (zum Beispiel [Dart SDK version: 3.12.2 (stable)]). Anders als bei Node.js und TypeScript, die getrennt installiert werden (eine Version von Node, eine Version von TypeScript), deckt die Versionsnummer des Dart SDK die Sprache, den Compiler und alle von [dart] gesteuerten Werkzeuge ab: Es gibt nur eine einzige Version, die Sie im Blick behalten müssen.

    2.2. Das VSCode-Projekt einrichten

    Wie bei TypeScript legen Sie einen Projektordner an und öffnen ihn in VSCode. Während ein TypeScript-Projekt mit zwei Dateien deklariert wird ([package.json] für die Abhängigkeiten, [tsconfig.json] für die Compiler-Optionen), genügt für ein Dart-Projekt eine einzige: [pubspec.yaml].

    2.2.1. Die Datei pubspec.yaml

    [pubspec.yaml] erfüllt sowohl die Rolle von [package.json] (Projektname, Abhängigkeiten) als auch, in geringerem Maße, die von [tsconfig.json] (der Schlüssel [environment: sdk:] legt den Bereich der akzeptierten Versionen des Dart SDK fest, ähnlich wie [target]/[lib] die von [tsc] angestrebte ECMAScript-Version festlegen):

    1
2
3
4
5
6
7
8
9
    name: dart_fundamentals
description: Scripts of the course "Introduction to the Dart language by example"
publish_to: 'none'
environment:
  sdk: '>=3.3.0 <4.0.0'

dependencies:
  http: ^1.2.0
  dio: ^5.4.0

    Anders als [package.json] (im JSON-Format) ist [pubspec.yaml] streng genommen eine YAML-Datei – die Einrückung ist darin bedeutsam, genau wie in Python.

    Sobald diese Datei geschrieben ist, lädt der Befehl [dart pub get] (Pendant zu [npm install]) die deklarierten Abhängigkeiten herunter und erzeugt eine Datei [pubspec.lock] (Pendant zu [package-lock.json]), die die genauen zu installierenden Versionen festschreibt.

    2.3. Erstes Skript

    Ein minimales Dart-Skript, [hello.dart]:

    1
2
3
    void main() {
  print('Hello Dart!');
}

    wird ausgeführt mit:

    1
    dart run hello.dart

    Zwei unmittelbare Unterschiede zum ersten TypeScript-Skript des Kurses: Die Funktion [main] ist hier OBLIGATORISCH (ein ausführbares Dart-Skript muss auf Dateiebene eine Funktion namens [main] definieren – anders als bei TypeScript/[tsx], wo der Code auf oberster Ebene der Datei direkt ausgeführt wird, ohne dass eine Funktion definiert werden muss); und [dart run] kompiliert und führt das Skript in einem einzigen Schritt aus, ohne sichtbaren separaten Transpilationsschritt (wie [tsx], aber ohne dass zusätzliche Werkzeuge installiert werden müssen: [dart run] ist Teil des SDK selbst).

    2.4. Zweites Skript: statische Analyse

    Während der TypeScript-Kurs zwischen einem Schritt „Typprüfung“ ([tsc --noEmit]) und einem getrennten ESLint-Schritt unterscheidet, fasst Dart beides in einem einzigen Befehl zusammen:

    1
    dart analyze

    Wird er ohne Argumente im Stammverzeichnis eines Projekts mit einer Datei [pubspec.yaml] ausgeführt, analysiert er alle Dateien [.dart] des Projekts: Er meldet sowohl Typfehler (das Pendant zu [tsc]) als auch Stilprobleme, die von den aktivierten Lint-Regeln erfasst werden (das Pendant zu ESLint) – wie Sie diese Regeln aktivieren, erfahren Sie im folgenden Abschnitt.

    2.5. Der Linter

    ESLint ist ein externes Werkzeug, das separat installiert und konfiguriert werden muss (Datei [eslint.config.js], Auswahl eines Presets usw.). Dart integriert seinen eigenen Linter direkt in [dart analyze]: Fügen Sie einfach das offizielle Paket [package:lints] zu den [dev_dependencies] der Datei [pubspec.yaml] hinzu und legen Sie dann im Stammverzeichnis des Projekts eine Datei [analysis_options.yaml] an:

    1
    include: package:lints/recommended.yaml

    Diese eine Datei erfüllt für den TypeScript-Kurs denselben Zweck wie [eslint.config.js]: Sie aktiviert einen vom Dart-Team empfohlenen Regelsatz (nicht verwendete Variablen, verdächtige Vergleiche, Bevorzugung von [const] usw.), den [dart analyze] anschließend automatisch anwendet.

    2.6. Die Dart-Erweiterung für VSCode

    Die offizielle Erweiterung [Dart] (Herausgeber: Dart Code), die über den Marktplatz für VSCode-Erweiterungen installiert wird, erfüllt genau denselben Zweck wie die ESLint-Erweiterung des TypeScript-Kurses, ist aber umfassender: Syntaxhervorhebung, automatische Vervollständigung, Anzeige der Fehler von [dart analyze] direkt im Editor und Ausführung von Skripten (die Schaltfläche [Run]/[Debug] über jeder Funktion [main]), ohne VSCode zu verlassen. Die Installation dieser einen Erweiterung genügt, um abzudecken, was der TypeScript-Kurs auf mehrere Erweiterungen verteilt.
