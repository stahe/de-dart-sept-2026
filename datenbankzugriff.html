    7. Datenbankzugriff

    Der TypeScript-Kurs widmet dem Zugriff auf eine MySQL-Datenbank drei Kapitel: den nativen Treiber [mysql2], gefolgt von zwei ORM ([TypeORM] und [Prisma]), jeweils mit demselben Beispiel – zwei Datenbanken, [dbpersons] (eine einzelne Tabelle) und [dbschool] (vier verknüpfte Tabellen: Klassen, Schüler, Fächer und Noten). Dieses Kapitel entspricht dem ersten und fasst dann die beiden ORM-Kapitel zu einem einzigen zusammen: Dart hat kein ausgereiftes Pendant zu [TypeORM] oder [Prisma] für MySQL (siehe die Randnotiz am Ende des Kapitels), und statt eine künstliche Entsprechung zu einem von beiden zu erzwingen, bauen wir ein „leichtgewichtiges ORM“, das zeigt, was ein ORM tatsächlich leistet, indem wir es selbst schreiben.

    7.1. Direkter Zugriff auf die Datenbank

    Das TypeScript-Paket [mysql2] hat auf der Dart-Seite kein Pendant, das vom MySQL-Team selbst gepflegt wird. Eine frühe Version dieses Kapitels verwendete [package:mysql1] (pub.dev/packages/mysql1), einen weit verbreiteten reinen Dart-Treiber für MySQL, der sich jedoch als inkompatibel mit MySQL 8.4 (der mit Laragon gelieferten Version) erwies: Selbst eine so einfache Abfrage wie „select 1“ scheiterte durchgängig mit dem Protokollfehler „Got packets out of order“, einem bekannten und ungelösten Fehler des Pakets (Issues GitHub adamlofts/mysql1_dart #112 und #161). Wir verwenden daher jetzt [package:mysql_client_plus] (pub.dev/packages/mysql_client_plus), einen aktiv gepflegten Fork, der mit MySQL 8.x getestet wurde und dessen API – [MySQLConnection.createConnection], [connection.connect], [connection.execute], [connection.close] – der von [mysql2] sehr ähnlich bleibt.

    7.1.1. Vorbereitung der Datenbank [dbpersons]

    Die Datenbank dbpersons enthält nur eine Tabelle, persons, die dasselbe Schema wie im Python-Kurs verwendet (Spalten id, first\_name, last\_name, age, mit einer Eindeutigkeitsbedingung für das Paar (last\_name, first\_name)). Das Skript sql/create_dbpersons.sql unten erstellt die Datenbank, den Anwendungsbenutzer und die Tabelle und fügt anschließend fünf beliebige Personen ein:

    -- create_dbpersons.sql
-- Erstellt die Datenbank [dbpersons] neu, die im Kapitel "Zugriff auf MySQL mit dem
-- nativen Treiber [mysql2]" verwendet wird, mit beliebigen Daten (die Originale des
-- Python/Flask-Kurses von 2020 sind nicht mehr verfügbar).
--
-- Verwendung:
--   mysql -u root -p < create_dbpersons.sql
--
-- Erstellt die Datenbank, den Anwendungsbenutzer [admpersons/nobody] (dieselben
-- Zugangsdaten wie im ursprünglichen Kurs) und die Tabelle [persons].

DROP DATABASE IF EXISTS dbpersons;
CREATE DATABASE dbpersons CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

CREATE USER IF NOT EXISTS 'admpersons'@'localhost' IDENTIFIED BY 'nobody';
GRANT ALL PRIVILEGES ON dbpersons.* TO 'admpersons'@'localhost';
FLUSH PRIVILEGES;

USE dbpersons;

CREATE TABLE persons (
  id         INT PRIMARY KEY,
  first_name VARCHAR(30) NOT NULL,
  last_name  VARCHAR(30) NOT NULL,
  age        INTEGER NOT NULL,
  UNIQUE (last_name, first_name)
);

-- beliebige Daten (dieselben Personen wie in den Beispielen des ursprünglichen Kurses)
INSERT INTO persons (id, first_name, last_name, age) VALUES
  (1, 'Paul',     'Langevin', 48),

    // mysql_01.dart
// Portiert databases/mysql/mysql-01.ts.
//
// Erster Schritt: Verbindung zur MySQL-Datenbank [dbpersons] herstellen und
// wieder trennen.
//
// [technische Entscheidung] Das TypeScript-Paket [mysql2] hat auf Dart-Seite kein direktes
// Äquivalent, das vom MySQL-Team selbst gepflegt wird. Eine erste
// Version dieses Kapitels verwendete [package:mysql1] (pub.dev/packages/
// mysql1), einen weit verbreiteten reinen Dart-MySQL-Treiber - der sich aber als
// inkompatibel mit MySQL 8.4 (mit Laragon ausgeliefert) erwies: Selbst eine
// so triviale Abfrage wie "select 1" scheiterte systematisch mit dem
// Protokollfehler "Got packets out of order" (bekannter, ungelöster Fehler des
// Pakets). Hier verwenden wir daher [package:mysql_client_plus]
// (pub.dev/packages/mysql_client_plus), einen aktiv gepflegten Fork, der mit
// MySQL 8.x getestet ist und dessen API - [MySQLConnection.createConnection],
// [connection.connect], [connection.execute], [connection.close] - der von
// [mysql2] sehr ähnlich bleibt.
import 'package:mysql_client_plus/mysql_client_plus.dart';

// Verbindung zur MySQL-Datenbank [dbpersons]
// die Identität des Benutzers ist (admpersons, nobody)
const String user = 'admpersons';
const String pwd = 'nobody';
const String host = 'localhost';
const int port = 3306;
const String database = 'dbpersons';

Future<void> main() async {
  // [Unterschied zu TypeScript] hier kein Union-Typ "MySqlConnection |
  // undefined": Ein nullbares Feld ([MySQLConnection?]) spielt dieselbe
  // Rolle - "noch nicht verbunden" wird durch [null] dargestellt, genau
  // wie "noch nicht verbunden" auf der TS-Seite durch [undefined] dargestellt wurde.
  MySQLConnection? connection;
  try {
    print('Connecting to the MySQL DBMS...');
    // [Unterschied zu TypeScript] anders als mysql1 (und mysql2) trennt
    // [mysql_client_plus] die ERZEUGUNG des Verbindungsobjekts
    // ([createConnection], das noch keinen Netzwerkaustausch durchführt) von
    // dem tatsächlichen Verbindungsaufbau ([connect], das das Protokoll
    // mit dem Server aushandelt) - zwei klar getrennte Schritte, wo
    // mysql1 sie in einem einzigen Aufruf [MySqlConnection.connect] zusammenfasste.
    // Wir weisen [connection] (die nullbare Variable des [finally]-Blocks) erst
    // zu, wenn [connect] erfolgreich war: Schlägt [connect] fehl, bleibt [connection]
    // [null], und das [finally] versucht nicht, eine Verbindung zu schließen,
    // die nie wirklich geöffnet wurde.
    final newConnection = await MySQLConnection.createConnection(
      host: host,
      port: port,
      userName: user,
      password: pwd,
      databaseName: database,
    );
    await newConnection.connect();
    connection = newConnection;
    // Fortsetzung
    print(
      "Successful MySQL connection to database=$database, host=$host as user=$user, passwd=$pwd",
    );
  } catch (error) {
    // den Fehler anzeigen
    print("The following error occurred: $error");
  } finally {
    // die Verbindung schließen, falls sie geöffnet wurde
    if (connection != null) {
      await connection.close();
    }
  }
}

    Kommentieren wir diesen Code:

    • Zeile 19: [import 'package:mysql_client_plus/mysql_client_plus.dart';]: der neue, vollständig in Dart geschriebene MySQL-Treiber, der [package:mysql1] ersetzt – dieses ist mit MySQL 8.4 (in Laragon enthalten) inkompatibel: Selbst eine so triviale Abfrage wie „select 1“ scheiterte durchgängig mit dem Protokollfehler „Got packets out of order“, einem bekannten und ungelösten Fehler des Pakets (siehe den Kommentar am Anfang der Datei).
    • Zeile 34: [MySQLConnection? connection;]: ein NULLABLE-Feld erfüllt exakt denselben Zweck wie der Union-Typ [MySqlConnection | undefined] in TypeScript – [null] steht für „noch nicht verbunden“, genau wie [undefined] in TS.
    • Zeilen 47–55: [final newConnection = await MySQLConnection.createConnection(...); await newConnection.connect(); connection = newConnection;]: [mysql_client_plus] trennt das ERSTELLEN des Verbindungsobjekts ([createConnection], das noch keinen Netzwerkverkehr verursacht) vom tatsächlichen Verbindungsaufbau ([connect], das das Protokoll mit dem Server aushandelt) – zwei getrennte Schritte, während [mysql1] (wie [mysql2] auf der TypeScript-Seite) sie in einem einzigen Aufruf zusammenfasste. [connection] (die nullable Variable aus [finally]) wird erst zugewiesen, nachdem [connect] erfolgreich war, sodass [finally] nie eine Verbindung schließt, die gar nicht geöffnet wurde.
    • [try] / [catch] / [finally]: identische Struktur wie in der vorherigen Version – die Verbindung wird in [finally] immer geschlossen, unabhängig davon, ob ein Fehler aufgetreten ist.

    // mysql_02.dart
// Portiert databases/mysql/mysql-02.ts.
//
// In diesem neuen Skript ist die Datenbankverbindung in eine
// Funktion ausgelagert.
import 'package:mysql_client_plus/mysql_client_plus.dart';

// verbindet sich (login, pwd) mit der Datenbank [database] auf dem Server
// [host] und trennt sich dann wieder; wirft eine Exception, wenn es ein Problem gibt
Future<void> connect(String host, int port, String database, String login, String pwd) async {
  MySQLConnection? cnx;
  try {
    // Verbindung - [createConnection] erzeugt das Objekt, [connect] handelt
    // wirklich mit dem Server aus (siehe den Kommentar in mysql_01.dart); wir
    // weisen [cnx] erst nach erfolgreichem [connect] zu, damit das [finally]
    // nie eine Verbindung schließt, die nicht zustande kam
    final newConnection = await MySQLConnection.createConnection(
      host: host,
      port: port,
      userName: login,
      password: pwd,
      databaseName: database,
    );
    await newConnection.connect();
    cnx = newConnection;
    print(
      "Successful connection to database=$database, host=$host as user=$login, passwd=$pwd",
    );
  } finally {
    // die Verbindung schließen, falls sie geöffnet wurde
    if (cnx != null) {
      await cnx.close();
      print('Successful disconnection\n');
    }
  }
}

// —————————————————————————————— main
// Zugangsdaten für die Verbindung
const String user = 'admpersons';
const String passwd = 'nobody';
const String host = 'localhost';
const int port = 3306;
const String database = 'dbpersons';

Future<void> main() async {
  // Verbindung eines vorhandenen Benutzers
  try {
    await connect(host, port, database, user, passwd);
  } catch (error) {
    // den Fehler anzeigen
    print('$error');
  }

  // Verbindung eines nicht vorhandenen Benutzers
  try {
    await connect(host, port, database, 'xx', 'xx');
  } catch (error) {
    // den Fehler anzeigen
    print('$error');
  }
}

    Kommentieren wir diesen Code:

    • Zeilen 10–36: [Future<void> connect(String host, int port, String database, String login, String pwd) async { ... }]: Die Verbindung ist in einer wiederverwendbaren Funktion gekapselt, die im Fehlerfall eine Ausnahme auslöst, statt sie selbst abzufangen – der Aufrufer entscheidet, was damit geschieht. Sie verwendet das Muster „Erstellen + [connect()]“ aus [mysql_01.dart] wieder: [cnx] wird erst nach erfolgreichem [connect] zugewiesen.
    • Zeile 43: [const int port = 3306;]: [mysql_client_plus] verlangt einen EXPLIZITEN Port ([createConnection]), während [ConnectionSettings] bei [mysql1] den Standardport (3306) selbst ableitete.
    • [main] ruft diese Funktion zweimal in zwei getrennten Blöcken [try] und [catch] auf: einmal mit gültigen und einmal mit ungültigen Zugangsdaten, um beide Pfade zu veranschaulichen.

    // mysql_03.dart
// Portiert databases/mysql/mysql-03.ts.
//
// Nachdem wir nun wissen, wie man sich verbindet, senden wir SQL-Anweisungen über die
// Verbindung: Wir erstellen die Tabelle [persons] der Datenbank [dbpersons] (neu).
import 'dart:io';
import 'package:mysql_client_plus/mysql_client_plus.dart';

// führt eine Update-Abfrage über die Verbindung aus
Future<void> executeSql(MySQLConnection connection, String query) async {
  await connection.execute(query);
}

// —————————————————————————————— main
// Zugangsdaten für die Verbindung
const String id = 'admpersons';
const String pwd = 'nobody';
const String host = 'localhost';
const int port = 3306;
const String database = 'dbpersons';

Future<void> main() async {
  // wir gehen Schritt für Schritt vor
  late final MySQLConnection connection;
  try {
    // Verbindung - [package:mysql_client_plus] führt, wie mysql1 vor ihm,
    // standardmäßig jede Abfrage in einer eigenen automatisch committeten
    // Transaktion aus (Äquivalent zu AUTOCOMMIT=True auf der Python-Seite)
    connection = await MySQLConnection.createConnection(
      host: host,
      port: port,
      userName: id,
      password: pwd,
      databaseName: database,
    );
    await connection.connect();
  } catch (error) {
    print("The following error occurred: $error");
    // [Unterschied zu TypeScript] `process.exit(1)` wird zu `exit(1)`
    // (dart:io) - gleiche Semantik, gleicher Exit-Code des Prozesses
    exit(1);
  }

  // Löschen der Tabelle persons, falls sie existiert
  // existiert sie nicht, tritt ein Fehler auf - wir ignorieren ihn
  try {
    await executeSql(connection, 'drop table persons');
  } catch (_) {
    // ignoriert - das [_] besagt, dass uns der Wert der Exception egal ist
  }

  // Erstellen der Tabelle persons
  const query = 'create table persons (id int PRIMARY KEY, first_name varchar(30) NOT NULL, last_name varchar(30) NOT NULL, '
      'age integer NOT NULL, unique(last_name,first_name))';
  try {
    await executeSql(connection, query);
    print('$query: query succeeded');
  } catch (error) {
    print("The following error occurred: $error");
  } finally {
    await connection.close();
  }
}

    Kommentieren wir diesen Code:

    • Zeilen 10–12: [Future<void> executeSql(MySQLConnection connection, String query) async { await connection.execute(query); }]: eine Hilfsfunktion zum Ausführen eines SQL-Änderungsbefehls (hier ein DROP TABLE gefolgt von einem CREATE TABLE) – [connection.execute(...)] ersetzt [connection.query(...)] aus [mysql1] (gleiche Aufgabe, neuer Methodenname auf der Seite von [mysql_client_plus]).
    • Zeile 41: [exit(1);] (aus [dart:io]): Äquivalent zu [process.exit(1)] – gleiche Semantik, gleicher Prozess-Exitcode bei einem Verbindungsfehler.
    • Zeile 47: [try { await executeSql(connection, 'drop table persons'); } catch (_) {}]: Dass [_] als Parameter an [catch] übergeben wird, zeigt an, dass der Wert der Ausnahme ignoriert wird – die Tabelle existiert möglicherweise einfach noch nicht.

// Portiert databases/mysql/config-04.ts.
//
// Konfiguration des Skripts [mysql_04]: Pfad der Datei mit den SQL-Befehlen
// und Zugangsdaten für die Datenbank [dbpersons].
//
// [Unterschied zu TypeScript] config-04.ts findet den Ordner des Skripts mit
// `dirname(fileURLToPath(import.meta.url))`. Dart hat ein direktes und
// kürzeres Äquivalent: [Platform.script] (dart:io) ist bereits die
// URI des laufenden Skripts - wir lösen einfach einen relativen Pfad dagegen
// mit [.resolve(...)] auf, ohne Stringverarbeitung. Nuance:
// [Platform.script] bezeichnet das HAUPTSKRIPT, das von `dart run` gestartet wird
// (mysql_04.dart), nicht diese Datei - anders als `import.meta.url`,
// das für jede Datei spezifisch ist. Das Ergebnis ist hier identisch, da
// config_04.dart und mysql_04.dart im selben Ordner liegen.
import 'dart:io';

class Config {
  final String commandsFilename;
  final String host;
  // [Migration zu mysql_client_plus] anders als bei mysql1, dessen
  // [ConnectionSettings] den Standardport (3306) selbst ableitete,
  // verlangt [MySQLConnection.createConnection] einen EXPLIZITEN Port - daher
  // fügen wir ihn hier der Konfiguration hinzu.
  final int port;
  final String database;
  final String user;
  final String password;

  const Config({
    required this.commandsFilename,
    required this.host,
    required this.port,
    required this.database,
    required this.user,
    required this.password,
  });
}

Config configure() {
  return Config(
    // Datei mit SQL-Befehlen, relativ zu DIESER Datei aufgelöst
    commandsFilename: Platform.script.resolve('data/commands.sql').toFilePath(),
    // Zugangsdaten für die Datenbankverbindung
    host: 'localhost',
    port: 3306,
    database: 'dbpersons',
    user: 'admpersons',
    password: 'nobody',
  );
}

    • Zeile 43: [Platform.script.resolve('data/commands.sql').toFilePath()] (aus [dart:io]): das direkte und kürzere Äquivalent zu [dirname(fileURLToPath(import.meta.url))] in TypeScript – [Platform.script] ist bereits die URI des gerade ausgeführten Skripts; es genügt, darin einen relativen Pfad aufzulösen.

Das Ergebnis ist hier dennoch korrekt, da [config_04.dart] und [mysql_04.dart] im selben Ordner liegen.
    • Zeilen 18–28: [class Config { final String commandsFilename; ...; final int port; ...; const Config({required this... }); }]: eine unveränderliche Klasse zur Bündelung der Konfiguration, wie das Interface [Config] der TypeScript-Version – mit einem zusätzlichen Feld [port], das von [MySQLConnection.createConnection] ausdrücklich verlangt wird (während [ConnectionSettings] aus [mysql1] den Standardport 3306 automatisch ableitete).

    // mysql_module.dart
// Portiert databases/mysql/mysql-module.ts: wiederverwendbare Funktionen, um
// eine Liste (oder eine Datei) von SQL-Befehlen auf einer offenen MySQL-
// Verbindung auszuführen.
//
// [Migration] Diese Datei verwendete anfangs [package:mysql1], das sich als

import 'dart:io';

// zeigt das Ergebnis eines SQL-Befehls an (Ergebnis eines execute() von
// mysql_client_plus)
// - wenn [results.cols] nicht leer ist, war es ein SELECT: wir zeigen die
//   Spalten, dann die Zeilen an;
// - andernfalls war es eine Update-Anweisung (INSERT/UPDATE/DELETE/DDL): wir
//   zeigen die Anzahl der geänderten Zeilen an ([results.affectedRows],
//   Äquivalent zum [rowcount] eines Cursors).
void _displayInfo(IResultSet results) {
  if (results.cols.isNotEmpty) {
    // es war ein SELECT - [cols] beschreibt die angeforderten Spalten
    final titles = results.cols.map((c) => c.name).toList();
    final header = titles.join(', ');
    print(header);
    print('*' * header.length);
    for (final row in results.rows) {
      print(titles.map((t) => row.colByName(t)).toList());
    }
    print('*' * header.length);
  } else {
    // keine beschriebenen Spalten - Update-Anweisung
    print('number of modified rows: ${results.affectedRows}');
  }
}

// verwendet die offene Verbindung [connection]
// führt auf dieser Verbindung die SQL-Befehle aus der Liste
// [sqlCommands] aus (ein Befehl pro Element; leere Zeilen oder Zeilen,
// die mit # beginnen, werden ignoriert)
// - bei verbose=true folgt auf jede Ausführung einer SQL-Anweisung eine
//   Anzeige, die Erfolg oder Fehlschlag angibt;
// - bei stop=true hält die Funktion beim 1. aufgetretenen Fehler an,
//   andernfalls führt sie alle Befehle aus;
// - bei withTransaction=true macht jeder Fehler alle zuvor ausgeführten
//   SQL-Anweisungen rückgängig (Rollback); andernfalls wird jeder Befehl
//   einzeln committet (Standardverhalten von MySQL, im AUTOCOMMIT);
// die Funktion liefert eine Liste [error1, error2, ...]
//
// [Unterschied zu TypeScript] mysql2 stellt direkt
// `connection.beginTransaction()/commit()/rollback()` bereit. [package:mysql1]
// (in einer ersten Version dieser Datei verwendet) stellte diese
// Methoden nicht einzeln bereit: Die Transaktion musste "von Hand" gesteuert werden,
// indem wir die SQL-Anweisungen [START TRANSACTION], [COMMIT] und
// [ROLLBACK] selbst sendeten. [package:mysql_client_plus] bringt schließlich das direkte Äquivalent
// von mysql2: `connection.transactional<T>((cnx) async { ... })` führt den
// Callback in einer Transaktion aus, committet (COMMIT) automatisch, wenn er
// normal endet, und macht automatisch rückgängig (ROLLBACK), wenn er eine
// Exception auslöst - keine SQL-Anweisungen zur Transaktionssteuerung mehr, die wir
// selbst schreiben müssten.
Future<List<String>> executeListOfCommands(
  MySQLConnection connection,
  List<String> sqlCommands, {
  bool verbose = false,
  bool stop = true,
  bool withTransaction = true,
}) async {
  final errors = <String>[];

  // führt die Befehle tatsächlich auf der übergebenen Verbindung [cnx] aus: Das ist
  // entweder [connection] selbst (ohne Transaktion) oder die "Arbeits"-
  // Verbindung, die [transactional] seinem Callback übergibt (mit
  // Transaktion) - die Schleife wird nur einmal für beide Fälle geschrieben
  Future<void> executeCommands(MySQLConnection cnx) async {
    for (final rawCommand in sqlCommands) {
      // führende und nachgestellte Leerzeichen des aktuellen Befehls entfernen
      final command = rawCommand.trim();
      // leerer Befehl oder Kommentar? weiter zum nächsten
      if (command == '' || command[0] == '#') {
        continue;
      }
      // Ausführung des aktuellen Befehls
      try {
        final results = await cnx.execute(command);
        // kein Fehler
        if (verbose) {
          print('[$command]: Successful execution');
        }
        _displayInfo(results);
      } catch (error) {
        final msg = '$command: Error ($error)';
        errors.add(msg);
        if (verbose) {
          print(msg);
        }
        // halten wir an?
        if (withTransaction || stop) {
          // mit Transaktion: wir werfen den Fehler erneut, damit
          // [connection.transactional] das ROLLBACK auslöst - bei
          // [package:mysql_client_plus] steuert die EXCEPTION
          // den Abbruch, nicht ein bloßes Verlassen der Schleife wie beim
          // manuellen ROLLBACK der mysql1-Version
          if (withTransaction) rethrow;
          return;
        }
      }
    }
  }

  if (withTransaction) {
    try {
      await connection.transactional((cnx) => executeCommands(cnx));
    } catch (_) {
      // der Fehler wurde oben bereits in [errors] erfasst; wir
      // schlucken ihn hier, um die Liste der Fehler normal an den
      // Aufrufer zurückzugeben, genau wie es die mysql1-Version tat (die nie
      // eine Exception aus dieser Funktion entweichen ließ)
    }
  } else {
    await executeCommands(connection);
  }
  return errors;
}

// verwendet die offene Verbindung [connection]
// führt auf dieser Verbindung die SQL-Befehle aus der
// Textdatei [sqlFilename] aus (ein Befehl pro Zeile)
Future<List<String>> executeFileOfCommands(
  MySQLConnection connection,
  String sqlFilename, {
  bool verbose = false,
  bool stop = true,
  bool withTransaction = true,
}) async {
  try {
    final content = await File(sqlFilename).readAsString();
    return await executeListOfCommands(
      connection,
      content.split('\n'),
      verbose: verbose,
      stop: stop,
      withTransaction: withTransaction,
    );
  } catch (error) {
    return ["The file $sqlFilename could not be processed: $error"];
  }
}

    // mysql_05.dart
// Portiert databases/mysql/mysql-05.ts.
//
// Parametrisierte Abfragen: einzelnes vorbereitetes Einfügen, dann
// Masseneinfügung. Hier erstellen wir die Tabelle [persons] mit dem Schema mit der Spalte [id] neu
// (wie im Skript mysql_03), damit dieses Skript unabhängig ist vom
// Zustand, den mysql_04 hinterlassen hat.
import 'package:mysql_client_plus/mysql_client_plus.dart';

// die Identität des Benutzers
const String id = 'admpersons';
const String pwd = 'nobody';
// der Rechner des DBMS
const String host = 'localhost';
const int port = 3306;
// Identität der Datenbank
const String database = 'dbpersons';

// [Unterschied zu TypeScript] `type Person = [id: number, lastName: string,
// firstName: string, age: number]` (ein TypeScript-Tupel, benannt, aber zur Laufzeit
// dennoch ein einfaches Array) wird hier zu einem POSITIONALEN Dart-3-RECORD
// (siehe dart-fundamentals/dart3/dart3_01_records.dart): dieselbe Idee einer
// "kleinen Gruppe typisierter Werte, ohne eine Klasse zu schreiben", aber ein echter
// eigener Typ, verschieden von einer [List].
typedef Person = (int id, String lastName, String firstName, int age);

Future<void> main() async {
  // Liste von Personen (id, lastName, firstName, age)
  final persons = <Person>[
    for (var i = 0; i < 5; i++) (i, 'l0$i', 'f0$i', i + 10),
    (40, "d'Aboot", "Y'éna", 18),
  ];

  // eine weitere Liste von Personen
  final otherPersons = <Person>[
    for (var i = 0; i < 5; i++) (i + 100, 'l1$i', 'f1$i', i + 20),
    (200, "d'Aboot", "F'ilhem", 34),
  ];

  // Zugriff auf das DBMS
  MySQLConnection? connection;
  try {
    // Verbindung - wir weisen [connection] erst zu, wenn [connect] erfolgreich war
    // (siehe den Kommentar in mysql_01.dart)
    final newConnection = await MySQLConnection.createConnection(
      host: host,
      port: port,
      userName: id,
      password: pwd,
      databaseName: database,
    );
    await newConnection.connect();
    connection = newConnection;

    // (Neu-)Erstellung der Tabelle mit dem Schema mit der Spalte [id] (siehe mysql_03)
    await connection.execute('drop table if exists persons');
    await connection.execute(
      'create table persons (id int PRIMARY KEY, first_name varchar(30) NOT NULL, last_name varchar(30) NOT NULL, '
      'age integer NOT NULL, unique(last_name,first_name))',
    );

    // Löschen der vorhandenen Datensätze
    await connection.execute('delete from persons');
    // Einfügen Person für Person mit einer parametrisierten Abfrage -
    // Destrukturierung des positionalen Records [person] direkt im
    // Kopf der for-Schleife (siehe dart-fundamentals/dart3/dart3_02_patterns.dart)
    //
    // [Unterschied zu TypeScript und zu mysql1] mysql2 (und mysql1, in
    // einer ersten Version dieses Skripts) verwenden POSITIONALE
    // PLATZHALTER ("?", einer LISTE von Werten in derselben
    // Reihenfolge zugeordnet). [package:mysql_client_plus] arbeitet anders: Die
    // Platzhalter sind BENANNT (":id", ":last_name"...) und einer [Map]
    // (Platzhaltername -> Wert) zugeordnet - hier aufwendiger zu schreiben, aber
    // so wird jede Abfrage unabhängig von der REIHENFOLGE der Parameter.
    for (final (idP, lastName, firstName, age) in persons) {
      await connection.execute(
        'insert into persons(id,last_name,first_name,age) values(:id,:last_name,:first_name,:age)',
        {'id': idP, 'last_name': lastName, 'first_name': firstName, 'age': age},
      );
    }
    // [Unterschied zu TypeScript] mysql2 bietet
    // `connection.query('insert ... values ?', [[[...],[...],...]])`, das
    // aus einem Array von Arrays selbst eine einzige Abfrage mit mehreren Zeilen baut.
    // [package:mysql_client_plus] hat kein solches Äquivalent (wie
    // mysql1 vor ihm): Wir bauen den SQL-Text also selbst, mit einer Gruppe
    // BENANNTER Platzhalter pro Zeile (":id0",
    // ":last_name0"... ":id1", ":last_name1"...), da benannte Platzhalter
    // in derselben Abfrage nicht wiederholt werden können - ein einziger Netzwerk-
    // Roundtrip, wie in der TypeScript-Version.
    final placeholderGroups = <String>[];
    final values = <String, Object?>{};
    for (var i = 0; i < otherPersons.length; i++) {
      final (idP, lastName, firstName, age) = otherPersons[i];
      placeholderGroups.add('(:id$i,:last_name$i,:first_name$i,:age$i)');
      values['id$i'] = idP;
      values['last_name$i'] = lastName;
      values['first_name$i'] = firstName;
      values['age$i'] = age;
    }
    await connection.execute(
      'insert into persons(id,last_name,first_name,age) values ${placeholderGroups.join(',')}',
      values,
    );

    // Commit der Transaktion - hier wurde jede Abfrage bereits automatisch
    // committet (MySQL ist standardmäßig im AUTOCOMMIT-Modus, wie der im
    // Skript mysql_03 erwähnte Standardmodus); es gibt also nichts
    // explizit zu committen
    print('${persons.length + otherPersons.length} persons inserted.');
  } catch (error) {
    print("The following error occurred: $error");
  } finally {
    if (connection != null) {
      await connection.close();
    }
  }
}

    7.2. Das leichtgewichtige ORM

    Der TypeScript-Kurs widmet dem Datenbankzugriff über ein ORM ([Object-Relational Mapping]) zwei getrennte Kapitel: [TypeORM], gefolgt von [Prisma], jeweils mit demselben Beispielschema. Beide beruhen auf einem gemeinsamen Prinzip: das Schema einmal beschreiben (mit TypeORM-Dekoratoren auf Klassen oder mit einer [.prisma]-Datei bei Prisma) und das Werkzeug dann beim Start oder bei der Kompilierung den gesamten Code erzeugen lassen, der Lese- und Schreibzugriffe auf Objekte in SQL übersetzt – einschließlich des Ladens von Beziehungen zwischen Tabellen.

    Dart hat für MySQL kein ausgereiftes und weit verbreitetes Pendant zu diesen beiden Werkzeugen: Es gibt zwar ORM-Bibliotheken für Dart, doch sie sind vor allem für Flutter/SQLite ([Drift], [Floor]) oder für andere Architekturen konzipiert – Prisma selbst bietet keinen Dart-Client an. Statt eine künstliche Zuordnung wie „dieses Dart-Paket = TypeORM“ oder „jenes Paket = Prisma“ zu erzwingen, verfolgt dieses Kapitel einen anderen, didaktisch sinnvolleren Ansatz: zu zeigen, was ein ORM tatsächlich leistet, indem man es selbst in einer bewusst minimalen Version schreibt – daher der Name [light ORM].

    // repository.dart
// Ein von Hand geschriebenes "Light-ORM": eine generische Klasse [Repository], stark
// inspiriert vom Repository von TypeORM (`AppDataSource.getRepository(...)`,
// `.find()`, `.findOneBy()`, `.save()`, `.delete()`), aber auf
// einer einzigen Tabelle aufgebaut, ohne Dekoratoren und ohne automatisches Laden von
// Beziehungen - siehe README.md für die ausführliche Diskussion dieser Entscheidung.
//
// [Migration] Diese Datei verwendete anfangs [package:mysql1]; sie wurde
// auf [package:mysql_client_plus] portiert (siehe den Kommentar in
// pubspec.yaml). Die für den Aufrufer sichtbarste Änderung ist der
// Stil der parametrisierten Abfragen: mysql1 verwendete POSITIONALE
// Platzhalter ("?" + Liste von Werten der Reihe nach), während
// [mysql_client_plus] BENANNTE Platzhalter (":column" + eine
// [Map] Spaltenname -> Wert) verwendet - was hier recht gut passt,
// da dieses Repository bereits [Map<String, Object?>] von
// Spalten verarbeitet.
import 'package:mysql_client_plus/mysql_client_plus.dart';

// [T]: der Typ der Entität, die von diesem Repository verwaltet wird (Person, SchoolClass...)
class Repository<T> {
  final MySQLConnection connection;
  // Name der SQL-Tabelle
  final String table;
  // Name der Primärschlüsselspalte
  final String keyColumn;
  // baut eine Entität [T] aus einer SQL-Ergebniszeile
  final T Function(ResultSetRow row) fromRow;
  // liefert die SQL-Spalten (Spaltenname -> Wert) einer Entität [T],
  // Primärschlüssel EINGESCHLOSSEN (nützlich sowohl für das Einfügen als auch für
  // die Aktualisierung)
  final Map<String, Object?> Function(T entity) toColumns;
  // extrahiert den Wert des Primärschlüssels einer Entität [T]
  final Object? Function(T entity) key;

  Repository(
    this.connection, {
    required this.table,
    required this.keyColumn,
    required this.fromRow,
    required this.toColumns,
    required this.key,
  });

  // Äquivalent zu `repo.find({ order: { column: 'ASC' } })`
  Future<List<T>> findAll({String? orderBy}) async {
    final sql = 'select * from $table${orderBy != null ? ' order by $orderBy' : ''}';
    final results = await connection.execute(sql);
    return results.rows.map(fromRow).toList();
  }

  // Äquivalent zu `repo.findOneBy({ column: value })` - [conditions] ist
  // eine "AND"-Gleichheit auf jeder übergebenen Spalte; die Schlüssel von [conditions]
  // dienen sowohl als SQL-Spaltenname als auch als Name des BENANNTEN Platzhalters
  // (":column") - sie werden daher unverändert als
  // Abfrageparameter wiederverwendet
  Future<T?> findOneBy(Map<String, Object?> conditions) async {
    final where = conditions.keys.map((c) => '$c = :$c').join(' and ');
    final results = await connection.execute(
      'select * from $table where $where limit 1',
      conditions,
    );
    if (results.rows.isEmpty) return null;
    return fromRow(results.rows.first);
  }

  // Äquivalent zu `repo.findOneByOrFail(...)` / `findOneOrFail(...)`
  Future<T> findOneByOrFail(Map<String, Object?> conditions) async {
    final found = await findOneBy(conditions);
    if (found == null) {
      throw StateError('No row found in [$table] for $conditions');
    }
    return found;
  }

  // Äquivalent zu `repo.save(entity)`: Einfügen, wenn der Schlüssel noch nicht
  // existiert, andernfalls Aktualisieren - genau das "Upsert"-Verhalten von
  // `save()` auf der TypeORM-Seite
  Future<void> save(T entity) async {
    final columns = toColumns(entity);
    final currentKey = key(entity);
    final alreadyExists = await findOneBy({keyColumn: currentKey}) != null;
    if (alreadyExists) {
      final toUpdate = columns.keys.where((c) => c != keyColumn);
      final assignments = toUpdate.map((c) => '$c = :$c').join(', ');
      // die zu aktualisierenden Spalten, PLUS der Schlüssel (unter demselben Platzhalternamen
      // wie in der WHERE-Klausel) - keine Kollision möglich,
      // da [keyColumn] gerade aus [toUpdate] ausgeschlossen wurde
      final values = <String, Object?>{
        for (final c in toUpdate) c: columns[c],
        keyColumn: currentKey,
      };
      await connection.execute('update $table set $assignments where $keyColumn = :$keyColumn', values);
    } else {
      final names = columns.keys.join(',');
      final placeholders = columns.keys.map((c) => ':$c').join(',');
      await connection.execute('insert into $table ($names) values ($placeholders)', columns);
    }
  }

  // Äquivalent zu `repo.delete({ column: value })`
  Future<void> delete(Map<String, Object?> conditions) async {
    final where = conditions.keys.map((c) => '$c = :$c').join(' and ');
    await connection.execute('delete from $table where $where', conditions);
  }
}

// statische Typ über den tatsächlichen Wert zur Laufzeit lügen kann. Auf der Dart-Seite hat
// [package:mysql_client_plus] eine ähnliche Falle, die aber vom Compiler SICHTBAR
// gemacht statt zur Laufzeit versteckt wird: Der typisierte Zugriff
// (`typedColByName<T>(...)`) kann eine DECIMAL-Spalte
// (interner SQL-Typ 246, "NEWDECIMAL") weder in [num] noch in [double] umwandeln - er
// löst `MySQLProtocolException: Cannot convert MySQL type 246 to requested
// type num` aus. Die einzige für JEDEN SQL-Typ garantierte Umwandlung ist
// [String]; also lesen wir die DECIMAL-Spalten mit
// `typedColByName<String>(...)` als [String] und wandeln sie dann selbst mit
// [num.parse] um - siehe [_decimal] unten.
import 'package:mysql_client_plus/mysql_client_plus.dart';

// liest eine SQL-Spalte DECIMAL/NUMERIC als [num] (siehe den Kommentar am
// Anfang der Datei)
num _decimal(ResultSetRow row, String column) => num.parse(row.typedColByName<String>(column)!);

// berechnet die Statistiken (gewichteter Durchschnitt, Min, Max) eines Schülers
Future<void> _studentStats(MySQLConnection cnx, int studentId) async {
  final studentRow = (await cnx.execute('select id, last_name, first_name from students where id = :id', {'id': studentId})).rows.first;
  print(
    'Statistics of student {"id":${studentRow.typedColByName<int>('id')},"lastName":"${studentRow.typedColByName<String>('last_name')}","firstName":"${studentRow.typedColByName<String>('first_name')}"}',
  );

  final grades = await cnx.execute(
    'select g.value as value, sub.name as subject_name, sub.coefficient as coefficient '
    'from grades g join subjects sub on g.subject_id = sub.id where g.student_id = :id',
    {'id': studentId},
  );

  if (grades.rows.isEmpty) {
    print('  no grades.');
    return;
  }

  num weightedSum = 0;
  num coefficientsSum = 0;
  num min = double.infinity;
  num max = double.negativeInfinity;

  for (final row in grades.rows) {
    // explizite Umwandlung über [_decimal] (siehe den Hinweis am Anfang der Datei):
    // [value] und [coefficient] sind somit echte [num]s, keine Strings
    final value = _decimal(row, 'value');
    final coefficient = _decimal(row, 'coefficient');
    weightedSum += value * coefficient;
    coefficientsSum += coefficient;
    if (value < min) min = value;
    if (value > max) max = value;
    print(
      '  grade=${value.toStringAsFixed(2)} subject="${row.typedColByName<String>('subject_name')}" '
      '(coefficient ${coefficient.toStringAsFixed(2)})',
    );
  }

  final average = weightedSum / coefficientsSum;
  print('  weighted average=${average.toStringAsFixed(2)}, min=${min.toStringAsFixed(2)}, max=${max.toStringAsFixed(2)}');
}

Future<void> main() async {
  final connection = await MySQLConnection.createConnection(
    host: 'localhost',
    port: 3306,
    userName: 'admschool',
    password: 'pwdschool',

  );

  try {

    // gewichteter Durchschnitt = (10*1.0 + 6*2.0) / (1.0+2.0) = 22/3 = 7.33

    print('');
    // Schüler id=21: Noten subject1=12 (Koeff. 1.0), subject2=8 (Koeff. 2.0)

    await connection.close();
  }
}

    7.2.7. Was das leichtgewichtige ORM nicht leistet

    Anders als TypeORM/Prisma: keine Schemagenerierung ([synchronize]/Migrationen), keine Dekoratoren, kein Lazy Loading und kein Identity Cache, kein Query Builder ([QueryBuilder]), und das Laden einer Beziehung ist IMMER eine zweite Abfrage oder ein von Hand geschriebener Join – nie automatisch. Das ist ein bewusster Kompromiss: genug, um das Repository-Muster anhand des Kursbeispiels zu veranschaulichen, ohne den Anspruch, ein echtes Repository in der Produktion zu ersetzen.
